# 工作区全量代码审核计划

## 目标与范围

审核手机版及其依赖模块的全部自有代码，找出会造成崩溃、数据丢失、错误结果、功能失效、状态错乱、敏感信息泄露或明显资源问题的缺陷，逐项提供可核查的证据。全量指约定范围内的逐文件覆盖，不限于最近提交或高风险文件抽查。

制定计划时的盘点基线为提交 `0b83cc5708a0ee9b5da7b38dc6f71997b225e328`（`0b83cc57`），盘点日期为 2026-11-11，新增本文前工作区干净。手机版及共享的 9 个 Gradle 模块共 420 个 Kotlin 生产代码文件、44,587 行；另有 `buildSrc/src/main/kotlin/Versions.kt`。当前未发现 `src/test` 或 `src/androidTest` 测试文件。正式开始时重新记录提交、工作区状态和文件清单，以实际文件内容为准。

覆盖范围：

- `app/phone`、`core`、`data`、`modes/film`、`setup`、`player/core`、`player/local`、`settings`、`logging` 的全部自有生产代码，包括公共组件、扩展函数、预览数据和实际存在的各源集。
- Manifest、资源 XML、数据库导出 schema、Gradle 配置、版本目录、`buildSrc`、混淆规则、lint 配置，以及 `.github/workflows`、Fastlane 等构建与发布接线。
- 工作区内未提交或未跟踪的自有代码：与已提交代码一并审核，并标明来源；执行时新增的验证材料也要登记。
- 文档用于定位入口和确认约定，尤其是 `AGENTS.md`、`wiki/pages.md`、`wiki/subtitle-download.md`、`wiki/release.md`；实现现状以源码为准，不能把文档写过的功能直接当成已经正确实现。

按仓库默认维护约定，`app/tv` 不纳入本轮逐文件业务审核，其现有 54 个 Kotlin 文件在覆盖清单中单列为范围外，不能算作已审。共享逻辑按自身契约审核，若发现问题也可能影响 TV，在该问题中注明，不另行开展 TV 界面、遥控器交互或设备验证。

生成代码、构建缓存和二进制资产不逐行审核；数据库导出 schema 虽由工具生成，仍须作为迁移契约核对。第三方 SDK、Media3、mpv 等依赖不做全量内部源码审计，但检查项目对其 API、线程、生命周期和配置的使用。`gradle/wrapper/gradle-wrapper.properties` 按仓库约定排除，不修改、不提交、不建议还原。

## 一、建立覆盖清单与验证基线

1. 从 Git 跟踪文件和未忽略的未跟踪文件建立文件级清单，结合 `settings.gradle.kts`、模块配置核对源集，避免只收集 `src/main/java` 而漏掉资源、配置和发布脚本。可用 `git ls-files --cached --others --exclude-standard` 作为盘点起点，去重后分类。
2. 每个范围内文件登记路径、模块、职责、所属审核批次、审核状态、关联问题编号和验证限制。覆盖状态区分“未读”“已读、需追踪”“已核查”“范围外及原因”；搜索命中、文件打开过或编译通过都不能直接算已核查。
3. 从 `wiki/pages.md` 的页面总览定位入口，再对照 `NavigationRoot.kt`、Activity、ViewModel 和实际调用补齐非独立页面的弹窗、播放器覆盖层与后台任务。文档缺项不能成为漏审理由。
4. 建立数据流与所有权清单：当前服务器/地址/用户、登录凭据、Repository 选择、下载文件及数据库记录、播放队列与进度、字幕文件/缓存、刮削与翻译结果。明确谁创建、谁修改、谁清理，以及切换账号后谁仍可能持有旧状态。
5. 当前没有现成测试，不照搬其他项目的“先跑全量单测”步骤，也不把 `check` 当作功能测试。记录可用的 IDE 诊断和本地验证条件；确需编译查错时才运行受影响模块的 Kotlin 编译任务，并记录命令、结果与环境阻碍。
6. 将制定计划、静态覆盖、问题验证和设备验收分别记录，不预填审核完成状态或测试通过结果。

## 二、按业务域逐文件审核

按以下顺序推进，以数据安全和核心行为优先。每批覆盖所属域的全部文件，同时追踪实际调用者与被调用者；同一文件涉及多个域时保留追踪项，直到相关契约都已核查。

### 1. 持久化、偏好与公共基础

- `data` 的实体、DAO、类型转换、数据库迁移、领域模型与 DTO 映射；`settings` 的 `AppPreferences`、设置模型及文件编辑逻辑；`logging` 和公共工具。
- 核对现有 schema 到当前数据库版本的迁移路径、字段默认值、主外键、级联删除、事务边界和升级后的数据可读性，不对真实用户数据库做迁移实验。
- 关注多服务器/多用户数据隔离、空字段与未知枚举、单位转换、偏好兼容与非法输入、文件编辑失败后的原文件保留，以及日志中的凭据、服务器地址和用户名。
- 同时核对模块实际依赖方向；架构或风格差异只有导致具体行为缺陷时才列入缺陷报告，其他必要建议单列。

### 2. 服务器、登录、启动与依赖装配

- `setup` 全部流程，手机端对应 Screen，`BaseApplication`、`MainActivity`、应用状态、Hilt 装配与导航根节点。
- `JellyfinApi` 初始化、服务器发现与地址选择、用户列表、登录、退出、切换服务器/用户，以及联网与离线 Repository 的选择时机。
- 关注地址与 token 的作用域、初始化顺序、重复提交、旧请求覆盖新账号状态、网络失败与认证失效、页面重建和进程恢复。
- 检查 Worker 与页面是否可能在账号切换后继续使用旧连接，导航副作用是否重复执行，离线模式能否落到可用入口。

### 3. Repository、浏览、搜索与分页

- `JellyfinRepository`、联网/离线两个实现、`ItemsPagingSource`，以及 `modes/film` 和手机端对应的首页、媒体库、下载列表、收藏、合集、电影/剧集/季/分集详情、人物与元数据筛选、搜索。
- 逐方法核对联网与离线行为：相同模型的必要字段是否齐全，不支持的操作是否被入口限制并明确反馈；不能要求离线实现执行只能联网完成的动作，也不能让无效操作静默成功。
- 关注分页起止与总数、排序稳定性、随机顺序、筛选参数组合、空页/重复项、刷新与加载更多竞争、搜索取消、旧结果回写和错误后重试。
- 检查收藏、已播放标记和详情刷新在列表、详情、继续观看与离线记录之间的一致性；核查删除或媒体源变化后的失效项处理。

### 4. 媒体修改与危险操作

- 元数据读取/编辑/保存/清空、封面抓取/预览/上传/删除、演员图片，以及删除媒体条目和关联文件的完整调用链。
- 核对操作绑定的服务器、用户、条目 ID 与媒体源，避免弹窗打开后切换对象、异步结果迟到或列表重排导致改错对象。
- 关注局部更新误清空未编辑字段、批量操作部分成功、重复点击、取消时已发生的服务端写入、失败反馈与刷新后状态。
- 检查不可逆操作的明确目标、权限与二次确认；区分“删除本地下载”和“删除服务器媒体及文件”，不能只检查按钮是否存在。

### 5. 下载、离线模式与后台同步

- `Downloader` / `DownloaderImpl`、下载状态模型及 ViewModel，`DownloadWorker`、`ImagesDownloaderWorker`、`SyncWorker`、`MpvCleanupWorker`，以及下载管理入口和应用调度代码。
- 跟踪媒体文件、封面、字幕、Trickplay、媒体源和用户数据从网络到临时文件、最终文件及 Room 的整个过程。
- 关注暂停/恢复/取消/删除/重试、重复任务、断点续传响应、磁盘不足、存储不可用、部分写入、进程中断恢复，以及数据库记录与文件不一致。
- 核对 Worker 唯一性、约束、重试、前台通知、资源释放和取消传播；检查任务删除后回写、清理任务误删使用中文件、账号切换后的任务归属。
- 追踪离线播放/收藏变化的持久化与联网回传，核查冲突处理、幂等性、失败后重试，以及旧离线状态覆盖较新的服务端状态的可能性。

### 6. 双播放器与播放生命周期

- `player/core`、`player/local` 全部代码，手机端 `BasePlayerActivity`、`PlayerActivity`、手势、预览拖动、截图、轨道与播放源选择等组件。
- 分别核对 ExoPlayer 与 mpv 从媒体源解析、鉴权/请求头、队列装配、续播、拖动、切集到退出释放的实际路径。
- 关注 ticks/毫秒/秒转换、未知时长、边界位置、轨道索引、自动连播、分段跳过、Trickplay 索引、切源后的状态保留，以及本地文件与在线 URL 的选择。
- 核查音频焦点、暂停/后台/画中画/返回、Activity 重建、监听注册与解绑、协程/定时刷新、播放器及 native 资源释放；连续进出播放页和快速切集时不能遗留旧回调。
- 追踪播放开始、进度和停止上报的条目归属及顺序，防止队列已切集而上一集位置被写到下一集，或停止事件重复覆盖最终进度。

### 7. 字幕下载、上传、侧载与对照

- `:core` 的 `dev.jdtech.jellyfin.core.subtitle` 包内全部流水线、状态/事件、解析、编码探测、时间计算与对照缓存，详情页和播放页共用入口，以及手机端 `dev.jdtech.jellyfin.presentation.player.subtitle` 包内的编排和覆盖层。
- 按 `wiki/subtitle-download.md` 核对实际契约：候选流式到达、语言与时长差、固定行次序、用户手选上传、取消剩余下载、失败后重试，以及两个入口的行为一致性。
- 检查 SRT/VTT、时间戳、异常尾部 cue、编码、空字幕与损坏输入；核对未知视频时长、时间偏移正负方向、单位和边界位置。
- 关注新搜索与旧结果竞争、重复上传、缓存目录/文件归属、临时文件原子替换、上传完成后的条目刷新与当前播放器侧载切轨。
- 核对真实字幕与对照面板的互斥，切集、关闭、画中画、退出时的恢复和清理；对照缓存不能串条目、串服务器或被旧任务重新写回。

### 8. 刮削、过盾、评论与翻译

- `:core` 中 `dev.jdtech.jellyfin.core` 下 scraper、comment、translator 三个包的全部接口与实现，JavDB 过盾页面、会话设置，以及详情页相关动作、弹窗与结果应用流程。
- 核对站点 URL、代理、Cookie、重定向、图片请求头、超时和取消，检查登录页/过盾页/空页是否会被当成正常结果。
- 关注番号/标题/人物匹配、HTML 解析与标签归一化、站点降级、部分成功、评论分页与缓存隔离、翻译结果映射及失败重试。
- 刮削与翻译结果应用到媒体前，核查条目身份、用户选择和字段保留；站点变化或模型输出异常只能作为待验证风险，不能凭猜测认定现有解析已失效。
- 默认用仓库已有材料或最小人工输入离线验证；确需真实站点确认时，另记外部依赖与待验证项，访问方式遵守本地代理约定。

### 9. 手机 UI、资源、系统接线与发布配置收尾

- 补齐前述各域未覆盖的 Screen、公共组件、主题、设置项、扩展函数和预览数据，逐项核对事件能否到达正确动作、状态变化是否驱动正确界面。
- 关注 Compose 副作用 key、状态保存、生命周期收集、弹窗关闭与任务取消、共享元素转场、快速返回/重复导航、窄屏/大字号下关键操作可达性，以及播放页 View 与 Compose 的接线。
- 按 Material 3 Expressive 约定核查 MotionScheme、空间/效果动效和中断行为；保留预测性返回关闭的既定配置。纯视觉偏好不混入功能缺陷。
- 核对 Manifest 组件/权限/导出、文件 URI 授权、网络安全配置、通知和前台任务的系统版本要求；检查资源限定符、引用、占位符及简繁中文关键文案。
- 静态检查 Gradle 变体、KSP/Hilt/Room 接线、R8 规则、依赖与版本配置、CI 和 Fastlane 的构建/发布目标、签名凭据引用及失败处理。不执行发布、上传或格式化脚本。

## 三、跨模块完整调用链复查

### 主线程卡顿专项（用户补充要求）

逐批追踪 UI / Main 入口 → 协程及线程切换 → 实际工作，补查此前已核查文件。独立核查同步数据库等待（含 `runBlocking` 等待 Room）、文件读写及目录遍历、锁与跨线程等待、图片解码/缩放/压缩、字幕或 HTML/JSON 解析、大集合排序/映射与重复计算。`suspend` 不等于自动切换后台线程；Room 的挂起 DAO 自行调度，不能误报为直接在主线程执行 SQL。

每个问题须记录可达调用者、实际 dispatcher / callback Handler、输入规模与阻塞操作；缺少设备测量时只说明阻塞风险和确定的工作量，不虚构耗时或 ANR。已有 IO 边界、短小内存操作与保护条件须一起核对。锁问题须证明主线程可参与竞争或等待，不能只凭出现 `synchronized` 收录。

逐域完成后，按完整用户行为再走一轮，核查模块交界处，避免局部实现分别合理而组合失效：

1. 冷启动 → 添加服务器/地址 → 登录 → 首页/媒体库 → 切换服务器或用户 → 返回与页面恢复。
2. 媒体库/搜索/筛选 → 列表分页 → 详情 → 收藏/已播放切换 → 返回列表并刷新。
3. 详情 → 刮削/翻译 → 编辑元数据或封面 → 保存/清空/删除 → 重新加载与缓存更新。
4. 详情 → 选择媒体源与存储位置 → 下载/暂停/恢复/取消 → 离线浏览与播放 → 删除下载及关联文件。
5. 离线收藏/播放进度 → 恢复联网 → 后台同步 → 服务端与列表更新；中途切换账号或重试。
6. 在线/离线播放 → 续播/拖动/切轨/切源 → 自动切集 → 画中画/后台 → 退出与进度回传；分别走 ExoPlayer、mpv。
7. 详情页或播放页搜索字幕 → 候选逐条到达 → 手选上传/失败重试 → 侧载或重新拉取 → 开关对照 → 切集/退出清理。
8. 删除媒体、移除服务器或退出用户时，已有下载、播放、刮削、字幕和同步任务如何终止、保留或恢复。

每条链覆盖正常路径，以及适用的空数据、错误输入、快速重复操作、并发完成、取消、网络/存储失败和生命周期中断。涉及进程重建时核对持久化与恢复代码；未进行设备验证的路径不得标成真机通过。

## 四、问题验证与去重

- 每个候选问题先确认可达入口、依赖版本和实际契约，再检查上下游保护、离线入口限制及线程/生命周期条件，不能只凭单行代码“看起来危险”就定为 Bug。
- 对迁移、分页、解析、文件操作和异步状态问题，优先用最小输入、隔离的临时目录、数据库副本或假实现复现。只在能验证独立契约、区分正确与错误行为时补最小回归材料，不引入整套测试框架，不写照抄实现的断言。
- 可用时先看已分析文件的 IDE 实时诊断；无诊断能力时如实记录。必要时仅运行受影响模块的 Kotlin 编译任务，例如 `./gradlew --offline :app:phone:compileLibreDebugKotlin` 或 `./gradlew --offline :data:compileDebugKotlin`，任务名以实际配置为准；缺缓存/SDK 与代码编译错误分开记录。
- Kotlin 编译可能带出必要的上游资源/生成代码任务，记录实际执行范围；编译成功只证明对应变体能编过，不能替代行为验证。
- 同一根因合并为一项，列明所有受影响入口和后端；不同根因即使现象相同也分别记录。
- 将“代码与契约足以确认的缺陷”“已离线复现的缺陷”和“依赖真机、服务端、站点或 native 行为才能确认的疑点”标清，严重度与确认程度分别判断。
- 交付前再次核对代码版本、文件位置、触发条件、用户影响与验证材料，排除不成立项；没有测试失败或编译错误不代表没有缺陷。

## 五、长程执行与交付

执行时持续维护覆盖清单和发现记录。每完成一个业务域或一轮完整调用链就更新检查点，记录已读文件、已核查文件、待追踪符号/调用链、候选问题、验证结果、剩余范围和阻碍。上下文切换后从检查点续审，不能把已读进度丢掉，也不能把未闭环追踪项提前算完成。

工作区变化时记录新增提交或未提交改动，重新核查受影响文件和相关调用链。报告的行号与证据必须对应实际审核版本，不能跨版本拼接结论。

正式审核产出：

- `docs/工作区代码审核报告.md`：按 P0/P1/P2/P3 排序列出已确认缺陷，另列待验证风险与验证限制。
- `docs/工作区代码审核覆盖清单.md`：文件级覆盖情况、范围外项、调用链复查进度、检查点和未完成项。
- 必要时在 `docs/审核证据/` 保存最小离线复现材料、输入与结果说明；材料不含真实凭据或用户媒体。

每项缺陷使用统一结构：

1. 编号、标题、严重度和确认程度。
2. 文件、精确行号与关键符号；必要时补充完整调用链位置。
