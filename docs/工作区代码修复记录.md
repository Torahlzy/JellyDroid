# 工作区代码修复记录

对应《工作区代码审核报告》的 JD-001～030，以及复审发现的三处生命周期回归。各项均已落实代码修改，尚未完成 Android 变体编译及真机验收；下列“修复”表示实现已改，不表示所有运行场景均已验证。没有修改数据库 schema、TV 独立页面或构建版本，也没有打包或推送。

## 下载与离线同步

- **JD-001**：`DownloadWorker.resolveFinalFile()` 用 `createNewFile()` 原子占位，重名编号耗尽抛出明确错误，重命名失败删除本次占位，不覆盖已有媒体。20 路并发同名和编号耗尽的隔离 JVM 探针通过。
- **JD-002**：DAO 新增基于上传快照的条件确认；只有播放位置、收藏、已播放字段仍完全相同才清除待同步位。内存 SQLite 已验证三个字段分别在请求期间变化时均保留脏标记。
- **JD-003**：暂时失败返回 `Result.retry()`；4xx（408、429 除外）保留脏数据并记录需要用户处理的失败。`UserDataSyncScheduler` 监听脏数据，触发带网络约束的唯一任务，15 分钟周期任务处理进程退出及任务结束交错的遗漏；周期与即时 Worker 串行上传，成功条目不重复上传。真实服务器恢复、认证失效和后台调度待设备验证。
- **JD-004**：ViewModel 管理下载准备 Job，并串行处理准备与取消；取消会等待准备清理，阻止旧任务进度重新进入界面。Downloader 在不可取消的 IO 清理段取消同一来源下主文件、字幕和封面任务，删除记录及临时内容。主文件已完成时可从 WorkManager 标签找回来源；收尾 SQL 校验 taskId，旧任务不能更新新任务或已删除记录。SQL 探针通过，WorkManager 取消时序待设备验证。
- **JD-007**：下载准备、Trickplay 写盘和删除目录统一在 IO；WorkManager 入队持久化完成后才继续，确保取消清理能找到任务。未测量主线程帧耗时。

## 线程、初始化和配置文件

- **JD-006**：截帧改为挂起接口，Main 只读取视图和提交 PixelCopy，裁剪、缩放及 JPEG 编码放在 Default；位图分配前限制宽度，复制回调结束后才允许回收。未进行设备截图和性能验收。
- **JD-008**：配置文件在 IO 读写，使用 Android `AtomicFile` 保存及恢复；State 暴露加载、保存和错误状态，失败通过 Snackbar 显示，保存失败保留编辑内容。加载成功前和保存期间禁用编辑、保存；磁盘故障场景待设备验证。
- **JD-009**：同步 DI provider 移除 `runBlocking`，轻量创建 API；Repository 提供挂起初始化，由 MainViewModel 在发布主页面状态前完成连接恢复。联网、离线实现均覆盖，播放器及封面 Worker 独立入口也初始化；不在主线程同步等待 Room。
- **JD-010**：字幕结果流、站点 HTML 与评论解析放在 Default；HTTP 正文在解压后设上限（HTML、字幕 8 MiB，其他二进制默认 32 MiB），避免无限读取。限额函数探针通过，未测量 Android CPU 和内存峰值。

## 字幕缓存与播放会话

- **JD-011**：时间戳支持合法 `MM:SS.mmm` WebVTT，同时保留 SRT、含小时 VTT 和 ASS。当前解析源码的编译及短/长格式样例通过。
- **JD-012**：缓存按条目用 Mutex 串行读取、写入、侧载和清理；批次令牌在锁内验证，临时文件使用唯一名称；迟到的异步清理仅清理对应批次。30 路追加无丢行、30 轮清理/旧写并发无复活的探针通过。
- **JD-013**：字幕候选及事件绑定服务器、用户、条目和下载代次；上传前后及事件消费前校验归属。切集、重新开播取消应用、关键词和面板加载任务，清理候选；上传使用固定连接和凭据的独立 SDK 客户端，应用侧载和切轨再校验播放会话。跨条目上传拒绝、取消后不发布成功事件的探针通过，真实切集待验证。
- **JD-014**：应用字幕解除 TEXT 禁用及旧轨覆盖，侧载配置使用唯一 URI id，轨道出现后通过 `TrackSelectionOverride` 明确选中本次字幕，不以轨道数量增加猜测目标。两后端实际显示待设备验证。
- **JD-015**：字幕重载记录条目、来源、列表下标与会话；网络返回后全部核对，真正重建前重新读取播放位置及播放状态。只忽略字幕重建造成的同条目 `PLAYLIST_CHANGED`，真正切集仍取消旧操作。网络期间 seek、暂停和切集待设备验证。
- **JD-016**：每次 cue 变化分别延迟排队，短句不被后续空 cue 取消；偏移变化、seek、切集和视图移除清理旧任务。真实类加 Handler 替身已验证 0～1 秒短句延迟 5 秒时在 5 秒出现、6 秒清除，以及 seek 清理。
- **JD-017**：首次对照准备与候选追加串行，清理后登记关联并重新读取全部 Ready 候选，准备期间到达的候选能补齐；事件发送在锁外，消费者暂停不阻塞追加。两条交错探针通过。

## 播放器、图片及详情页

- **JD-005**：mpv 默认 `tls-verify=yes`。没有添加信任所有证书或关闭校验的兼容回退；native CA 链、有效证书、错误主机名、过期与自签名证书仍需设备验证。
- **JD-018**：短暂失焦与恢复同时更新 mpv 原生 pause 和 Media3 逻辑状态；永久失焦不自动恢复，用户主动暂停会清除自动恢复标记。音频焦点场景待设备验证。
- **JD-019**：三个播放器 DialogFragment 均改为无参构造，`activityViewModels()` 获取共享 ViewModel，选轨参数放 arguments，菜单动作通过宿主 Host 取回。构造调用已核对，旋转与进程恢复待设备验证。
- **JD-020**：检查封面和截帧前后均核对条目及播放会话，切集后丢弃截帧结果，不上传给旧条目。实际慢请求切集待验证。
- **JD-021**：视频宽高缺失或非正数时只省略分辨率标记，不再非空断言导致整页加载失败，其余元数据保留。
- **JD-022**：先上传再清理旧图。已核对 Jellyfin 10.10.7 的 `ImageController`、`ImageSaver`：单图直接覆盖，背景图追加；同类背景图全部上传成功后，按倒序删除上传前的旧索引。上传失败时保留旧图；部分上传成功、清理失败时允许新旧并存并反馈错误，避免先删造成数据丢失。未向真实服务器上传图片。
- **JD-023**：封面下载逐文件检查完整性，目录存在不会阻止缺图补下；唯一临时文件下载成功后再发布，失败返回 retry，取消不吞异常。真实断网、重试和进程重建待验证。
- **JD-024**：移除界面保存的 initialLoad，ViewModel 的首次 setup 负责加载，同实例 setup 幂等；进程重建时新 ViewModel 正常拉取列表。实际进程恢复待验证。
- **JD-025**：发现服务器按 id 去重，State 每次接收 `toList()` 不可变快照，不共享被后续修改的列表。
- **JD-026**：电影、剧集、季和分集详情统一显示错误详情和重试入口；无内容时停止等待动画，返回仍可用；已有内容不清空。重试先清除旧 error，取消异常继续传播。Material3 错误卡复用既有组件，视觉待设备验证。

## 复审回归修复

- **冷启动恢复播放页**：字幕关键词和打开对照面板的入口先等待 `repository.initialize()`，再读取连接与用户信息；初始化失败进入已有提示，不再同步触发未恢复用户的非空断言。
- **离开详情页取消已入队下载**：下载准备由现有单例 Downloader 的独立协程作用域承接，同来源复用准备任务。页面退出只结束等待；用户主动取消通过专用取消原因停止准备并等待清理。重新进入详情页后的取消或删除同样先停止遗留准备，避免删除后继续入队。
- **过期对照加载提前显示面板**：Manager 在发布任何面板状态前校验加载代次和播放目标。初次同条目媒体切入只改变播放会话时重新加载，切条目或换账号则放弃；关闭面板也使正在加载的结果失效。面板显示与隐藏真实字幕在有效会话中一并完成。
